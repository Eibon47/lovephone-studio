# LovePhone Studio｜小手机工坊 DIY 自用版 MVP 方案

## 1. 产品定位

LovePhone Studio｜小手机工坊，第一版先不要做成大平台，也不要做模板市场。它应该先是一个给用户自己用的“小手机搭建器”。

它解决的问题是：

> 我想拥有一个专属于我的 AI 角色陪伴小手机，但我不会开发，也不想折腾复杂配置。

第一性原理上，小手机不是核心，情绪陪伴感才是核心。用户不是为了得到一个 JSON，也不是为了配置一个工具，而是想快速得到一个“像我的角色”“属于我”“看起来就想点进去”的陪伴物。

所以第一版最重要的不是功能多，而是低门槛和即时心动。用户打开页面后，应该先看到一个已经很好看的小手机，再通过少量修改把它变成自己的。

第一版应该让用户感觉自己是在“捏一个小手机”，而不是在填后台表单。

第一版的核心目标：

> 让用户在 3 分钟内生成一个看起来属于自己的 AI 陪伴小手机，并愿意保存、截图或继续编辑。

## 2. 旧 Demo 怎么看

你之前的 demo 可以看作一个“小手机运行时原型”。它已经证明了这个形态是成立的。

旧 demo 里已经有：

- 手机外壳
- 灵动岛
- 启动页
- 锁屏页
- 桌面
- Dock
- App 图标
- 聊天页
- 角色管理
- 记忆页
- 回忆页
- 日记
- 恋爱时间线
- 关系档案
- 日程表
- 设置页
- 主题、壁纸、字体
- 本地存储
- 用户自己填写 API Key 的聊天接入
- 语音相关配置

这说明你不是从 0 证明“小手机能不能做”，而是要把它升级成“普通人也能搭出来”。

旧 demo 最值得复用的是：

- 手机壳和手机比例
- 锁屏、桌面、聊天页的视觉形式
- 幻想风主题素材
- App 图标和 Dock 形式
- 本地保存的思路
- 用户自填 API Key 的方向

不建议直接照搬的是：

- 很大的单文件 `script.js`
- 所有功能都塞进小手机内部设置页
- 第一版就开放太多 App
- 复杂桌面拖拽
- 真实聊天、记忆、关系成长、日程生成等完整运行逻辑

新项目更适合做成：

> 外部搭建器 + 右侧小手机实时预览。

## 3. 第一版 MVP 范围

第一版只做一个单页搭建器，但不要从空白开始。用户打开页面时，默认先进入一个已经好看的模板，然后再进行微调。

推荐流程分四步：

1. 选择模板与角色
2. 选择外观
3. 选择陪伴方式
4. 生成预览和保存

页面布局建议：

- 左边是配置面板
- 右边是实时小手机预览
- 顶部显示产品名和步骤
- 底部或右上角放保存、重置、导出、导入

第一版必须做：

- 3 到 5 个一键模板
- 角色名字
- 用户昵称，或者角色怎么称呼用户
- 关系类型
- 少量性格标签
- 说话风格预设
- 开场白预设和可编辑输入
- 主题选择
- 壁纸选择
- 字体风格，第一版可以只做 2 到 3 种
- 手机壳样式，第一版可以只做 2 到 3 种
- 陪伴方式开关
- 实时预览
- 保存到本地
- 导出配置 JSON
- 导入配置 JSON
- 重置为默认配置

第一版模板建议：

- 温柔恋人
- 陪伴搭子
- 安静守候
- 日记陪伴
- 幻想旅人

模板的作用不是限制用户，而是减少第一步的心理成本。用户先选一个接近想象的起点，再改名字、关系和外观。

第一版陪伴方式只保留：

- 聊天
- 记忆
- 日记
- 纪念日 / 时间线
- 晚安问候

第一版不要做：

- 登录注册
- 云端同步
- 模板广场
- 付费系统
- 公开分享
- 创作者主页
- 复杂拖拽布局
- 桌面图标自由摆放
- 多模型管理
- 完整长期记忆系统
- 语音生成
- 语音识别
- 内容审核后台

## 4. 配置 JSON

配置 JSON 是技术核心，不是产品核心。用户真正感知到的是“小手机变成了我的”，JSON 只是底层保存结果。

产品体验应该是：

```text
用户选择模板
  -> 小手机立即变样
  -> 用户改角色和外观
  -> 小手机继续实时变化
  -> 用户保存
  -> 底层生成配置 JSON
```

从工程角度看，用户搭出来的小手机，本质上仍然是一份配置。

以后不管是网页、小手机运行时、桌面端，还是模板导入导出，都可以读这一份配置。

建议第一版配置结构：

```json
{
  "version": 1,
  "meta": {
    "title": "我的小手机",
    "templateId": "gentle-lover",
    "createdAt": "",
    "updatedAt": ""
  },
  "character": {
    "name": "小甜心",
    "userName": "我",
    "relationship": "恋人",
    "personality": ["温柔", "有点黏人"],
    "speakingStyle": "轻声、关心、偶尔撒娇",
    "greeting": "你回来啦，今天过得怎么样？",
    "avatar": {
      "type": "preset",
      "value": "heart"
    }
  },
  "theme": {
    "id": "fantasy",
    "wallpaper": "sage-parchment",
    "fontStyle": "system",
    "primaryColor": "#7FB59A",
    "phoneFrame": "dark"
  },
  "components": {
    "chat": true,
    "memory": true,
    "diary": true,
    "anniversary": true,
    "goodnight": true
  },
  "model": {
    "mode": "not-configured",
    "apiKeyMode": "user-provided"
  },
  "memory": {
    "enabled": true,
    "mode": "local-basic"
  },
  "voice": {
    "enabled": false
  }
}
```

注意：第一版不要把 JSON 做得太大。只有会影响预览或保存结果的字段，才应该进入配置。

## 5. 页面体验

小手机预览是这个产品最重要的地方。第一版要先让用户心动，再让用户配置。

第一屏不应该是介绍页，也不应该是营销落地页，而应该直接进入搭建器。

推荐布局：

- 左边配置区宽度约 360 到 440 px
- 右边居中显示小手机
- 移动端可以切换“编辑 / 预览”两个视图
- 步骤名称保持简单：模板与角色、外观、陪伴、预览

模板页：

- 显示 3 到 5 个视觉模板卡片
- 每个模板直接预填角色气质、主题、壁纸和陪伴方式
- 用户点击模板后，右侧小手机立即变化
- 模板文案不要讲参数，要讲感觉，比如“温柔恋人”“安静守候”“幻想旅人”

角色页：

- 角色名字输入框
- 用户昵称输入框
- 关系类型按钮：恋人、朋友、搭子、家人、自定义
- 性格标签选择
- 说话风格预设
- 可选补充描述
- 开场白输入框

外观页：

- 主题卡片
- 壁纸缩略图
- 字体风格选择
- 手机壳样式选择
- 主色选择

陪伴方式页：

- 每个陪伴方式一行
- 用开关控制是否启用
- 不讲技术细节，只告诉用户它会在小手机里出现什么

预览页：

- 显示保存状态
- 导出 JSON
- 导入 JSON
- 重置配置
- 后续可以加“打开生成的小手机”

## 6. 小手机预览怎么做

第一版预览不需要完整复刻旧 demo 的所有功能，只要让用户看到“我搭出来的小手机长什么样”。

预览需要显示：

- 手机外壳
- 状态栏
- 桌面壁纸
- 桌面便签或小组件
- 根据陪伴方式开关显示 App 图标
- Dock
- 简化聊天页

配置和预览的对应关系：

- 换模板，角色气质、主题、壁纸、陪伴方式一起变化
- 改角色名字，锁屏、桌面、聊天页都同步更新
- 改开场白，聊天预览第一句话同步更新
- 改壁纸，桌面和聊天背景同步更新
- 改字体，整个小手机字体同步更新
- 关闭聊天，桌面不显示聊天图标
- 关闭记忆，桌面不显示记忆图标
- 关闭日记，桌面不显示日记图标
- 关闭纪念日，桌面不显示时间线图标
- 开启晚安问候，桌面便签显示晚安相关内容

第一版最好让用户可以点击“聊天”图标，让右侧预览切到聊天页。这个小交互会让 demo 更像真的手机。

## 7. 技术方案

第一版建议做成纯前端静态应用：

- 不需要后端
- 不需要登录
- 不需要数据库
- 本地存储配置
- 支持导入导出 JSON
- 从旧 demo 复制必要的主题图片和图标素材

推荐技术路线：

- 可以用 Vite + 普通前端
- 也可以先用纯 HTML / CSS / JS
- 如果要长期维护，建议从一开始就拆模块

推荐目录结构：

```text
src/
  main.js
  config/
    defaultConfig.js
    templates.js
    schema.js
  builder/
    BuilderApp.js
    TemplatePanel.js
    CharacterPanel.js
    AppearancePanel.js
    CompanionPanel.js
    PreviewActions.js
  preview/
    PhonePreview.js
    HomePreview.js
    ChatPreview.js
    previewMapping.js
  storage/
    localConfigStore.js
  styles/
    base.css
    builder.css
    phone-preview.css
  assets/
    theme-fantasy/
```

如果不用框架，也可以照这个思路拆成多个 JS 模块。

## 8. 数据流

数据流要保持简单：

```text
用户修改配置
  -> 更新 config
  -> 校验和整理 config
  -> 保存草稿到本地
  -> 重新渲染左侧表单
  -> 重新渲染右侧小手机预览
```

小手机预览不要自己保存一套复杂数据。它应该尽量只从 config 读取内容。

如果预览里有“当前看桌面还是聊天页”这种状态，可以单独作为 UI 状态，不放进最终配置。

本地存储 key 建议：

- `lovePhoneStudioConfig`
- `lovePhoneStudioLastExportName`

不要直接复用旧 demo 的一堆 `lovePhone*` key，避免互相污染。

## 10. 测试清单

第一版完成时，需要检查：

- 默认配置能正常渲染
- 切换模板后，小手机预览立即变化
- 修改角色名字后，预览里所有相关位置都会更新
- 修改开场白后，聊天预览会更新
- 修改主题后，小手机样式会变化
- 开关陪伴方式后，桌面图标会增加或减少
- 保存后刷新页面，配置还在
- 重置后恢复默认配置
- 导出的 JSON 是合法 JSON
- 导入合法 JSON 能恢复配置
- 导入错误 JSON 时有清晰提示
- 桌面端布局不挤
- 手机端布局可用
- 按钮、卡片、小手机里的文字不重叠

建议检查这些屏幕尺寸：

- 1440 x 900
- 1280 x 720
- 390 x 844

## 11. 实现顺序

建议按这个顺序做：

1. 搭一个静态应用骨架
2. 建默认配置和本地保存
3. 做右侧手机预览壳子
4. 接入幻想主题素材
5. 做 3 到 5 个一键模板
6. 做角色配置面板
7. 做外观配置面板
8. 做陪伴方式开关面板
9. 做导入、导出、重置
10. 做响应式适配
11. 做视觉检查和体验打磨

第一版完成标准：

> 用户打开页面，先看到一个好看的小手机，选择模板，改角色名字和外观，勾选陪伴方式，右侧小手机实时变化，并且可以保存和导出配置。

这就够了。

第一版的目标不是“功能完整”，而是证明：

> 小手机可以被普通人搭出来，而且过程简单、好看、好玩，让用户觉得“这是我的”。

## 12. MVP 成功指标

第一版不要只用“做完功能”来判断成功，要看它有没有击中用户。

建议用这些指标判断：

- 用户能否在 3 分钟内生成一个小手机
- 用户是否愿意点击保存
- 用户是否愿意导出配置
- 用户是否愿意截图发给别人看
- 用户是否会说“这个像我的角色”
- 用户是否愿意回来继续改它

其中最关键的是：

> 不是生成了一个手机就成功，而是用户觉得“这是我的小手机”。
